## How we work together

1. We work on one checkpoint at a time. Each has its own [personal note](checkpoints/).
2. Codex prepares the work and tells you what is needed.
3. For a visual checkpoint, you generate references outside this project and save them as described
   in its brief. Codex opens the files and checks what is feasible. You approve the chosen look first.
4. Codex builds and checks the change, then shows real screenshots or recordings.
5. You follow a short checklist. Codex handles setup, commands, diagnosis and repairs.
6. You approve the tested version or ask for changes. We then prepare the next checkpoint.

You normally only supply images, choose a look, answer important product questions, test briefly and
approve. You do not need to read source code or diagnose bugs. Image approval and app approval are
separate decisions. Codex cannot approve either for you.

Use [Visual references](VISUAL_REFERENCES.md), [Testing](TESTING.md), [Feedback and approval](FEEDBACK.md)
and [Quick recovery](RECOVERY.md) when needed. Each personal note says what to provide, what will change,
what to test and how to approve. The progress page is updated from the same record Codex uses.

The order is safe setup → safety checks → file-drag feasibility → shared look → four modes →
activities → Dock/Hybrid → Shelf → clipboard → settings/core tools → final release checks.
Only CP-03 through CP-09 need newly generated visuals. Later images must follow the earlier approved look.
