# Asset, data and IP release gate

This is a source inventory, not a legal opinion or a declaration that all material is clear to ship. The [MIT source license](../LICENSE) and its k4ditano notice must be preserved. It does not independently establish ownership or redistribution terms for every image, dataset, font, sound, trademark or remotely loaded file. Keep optional inherited modules available during development; gate **distribution** of each questionable payload until provenance and rights are documented.

| Category and evidence | Current classification | Release action |
| --- | --- | --- |
| k4 source/QML/helper code, [`LICENSE`](../LICENSE) | **Permissively licensed for source** under the repository's MIT notice; third-party snippets still need individual review if found. | Preserve MIT copyright and license notice in copies; record any separately licensed imports. |
| Game sprite PNGs (`plugins/Game/assets/`, 104 PNGs) | **Uncertain.** Files are bundled; no per-file creator/license manifest was found in this pass. Do not infer rights from MIT code license. | Obtain creator/source records and distribution grant, or **replace before release** if provenance cannot be established. |
| Digivice packaged data (`plugins/Digivice/datos/`, seven JSON files including species, descriptions and sprite metadata) | **Attribution required / possible share-alike obligations / uncertain scope.** [Inherited guide](k4-reference/DIGIVICE.md) and [`services/Digivice.qml`](../services/Digivice.qml) claim digi-api/Wikimon provenance and CC-BY-SA 3.0. The [DAPI site](https://digi-api.com/) confirms mixed official/fan sources but did not establish a blanket redistribution license in this check. | Trace each dataset field/source/version, obtain authoritative terms, add required attribution/share-alike notices where applicable, and review franchise text/names separately. If rights remain unclear, exclude/replace the affected data before public distribution. |
| Digivice bundled backgrounds, egg PNG and 18 WAV sounds (`plugins/Digivice/`) | **Uncertain.** Bundled non-code media has no per-file provenance manifest found here. | Record creator, source and license per file; **replace before release** if permission cannot be shown. |
| Digivice/Wikimon/digi-api franchise images fetched at runtime (`services/Digivice.qml`, `plugins/Digivice/Retrato.qml`) | **Remote-only/not redistributed in the repository**, according to source; source says imagery is Bandai material cached on first use. Remote loading is not a grant of reuse rights. [Wikimon disclaimer](https://wikimon.net/Wikimon:General_disclaimer) disclaims ownership of Bandai material. | Decide whether this feature can ship with remote imagery and clear network disclosure; otherwise disable/replace that imagery path for release. Do not repackage user cache as project assets. |
| Medabots names/design concepts and [`k4-reference` plans](k4-reference/MEDABOTS_ASSETS.md) | **IP/branding uncertain; no `plugins/Medabots/` runtime directory in this snapshot.** The inherited plan calls for original art and no ROM sprites but is a proposal, not proof of rights. | Do not claim a shipped Medabots module; review names/trademarks and any future assets before release. Use independently documented original art if the concept is pursued. |
| Fonts/icons (Meslo Nerd Font, Adwaita, Nerd glyphs), shaders and other QML visual assets | **Attribution/license verification required.** Current dependency and theme code uses fonts/glyphs and shader effects; exact bundled-versus-system-file terms were not established by this pass. | Inventory files and package sources, retain required notices, verify any redistribution of font/icon binaries and imported shader code. Do not rebrand third-party artwork as project-owned. |
| Repository screenshots/GIFs (`screenshots/`, 10 PNG and two GIF files) | **Uncertain as distributable marketing material.** They are bundled project captures, potentially depicting third-party apps/art. | Check capture provenance, visible third-party marks/assets and permitted reuse before publishing them under the new brand. |
| New project-created visuals and sounds, if later produced | **Clearly owned/project-created only after creator/source records exist.** No blanket claim applies yet. | Keep a per-asset manifest: path, creator, source file, date, tool/source material, license/permission, attribution, modifications and release decision. |

“Permissively licensed,” “attribution required,” and “share-alike” are **file-specific statuses**, not defaults inherited from the code license. No bundled non-code category above was verified as universally permissive. A downloaded image is not the same as a redistributed file, but its use, caching, remote disclosure and branding still require review. The release checklist must resolve each uncertain or replace-before-release row, include required notices, and document any excluded optional module/data; this is a release gate rather than a reason to refactor or delete code in the research phase.
