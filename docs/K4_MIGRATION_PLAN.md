# k4 component migration map — proposal only

No product code is changed by this plan. Preserve first, characterize behavior second, then make the smallest targeted change. The verdict column concerns **future treatment**; [support tiers](V1_SPEC.md#support-tiers-and-release-gates) concern release validation. No `REPLACE` or `REMOVE` candidate is currently supported by evidence. Any future removal needs proof, user impact and a compatibility path under [D14](DECISIONS.md). Keep inherited paths, public APIs, settings IDs and IPC verbs where practical so plugins and selective [upstream sync](UPSTREAM_SYNC.md) remain manageable; do not compromise the product architecture just to ease cherry-picks.

## Compatibility work before any plugin API change

Record current `K4.Plugin` properties/signals, all `api/K4` exports, manifest keys (`permisos`, `superficies`, `host`, `requiere`, `aplicacion`), lifecycle and IPC verbs. Test `ejemplos/hola`, `piezas`, `efectos`, `snake` and at least one installed external plugin if the user supplies one. `tools/plugins.py` static checks do not sandbox runtime code. A new activity or dock contribution is optional and additive; old `view` remains renderable. Disabled means uninstantiated; hot reload and failure diagnostics remain. Any unavoidable break requires versioned manifest/API migration and a documented fallback before implementation.

## Tiered validation and upstream balance

- **Core v1:** shell/Island/modes, Dual dock, host Activity Policy, media, Owned notifications, clipboard, Shelf, control-center essentials, settings and plugin host block release when broken. External notification mode must stay usable without claiming history/actions.
- **Supported inherited:** editor/capture depth, wallpaper/theme, Files search, terminal/SSH, window tools, agents, session and inherited Tienda keep startup/key-workflow smoke coverage; changed paths receive regression checks.
- **Experimental/optional inherited:** Game/Digivice (catalog default-off) and Atalaya live previews (catalog default-on despite GPU cost) remain available, with no major v1 redesign promise. Safety, severe idle cost and [asset rights](ASSET_LICENSE_AUDIT.md) can block distribution of a payload/default; they do not authorize deletion in this plan.

When importing upstream k4, cherry-pick isolated compatible fixes or manually port high-divergence changes to `shell.qml`, `Dual`, Theme, Settings and PluginManager. Record source SHA/attribution and rerun plugin/API checks. Retain module paths until a real architectural reason justifies a move, but never preserve a poor boundary merely to simplify full merges. See [UPSTREAM_SYNC.md](UPSTREAM_SYNC.md).
