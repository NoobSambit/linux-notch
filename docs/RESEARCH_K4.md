# k4 source audit

Research date: 2026-09-25. Scope: the inherited files in this workspace, read only. The source initially arrived without upstream Git ancestry. A later content comparison identified the exact upstream base: **[`5b1406c2267440c97c4c9986a9fa19c7424094c0`](https://github.com/k4ditano/k4/commit/5b1406c2267440c97c4c9986a9fa19c7424094c0)**; all 535 shared paths in local first commit `9fba900` had the same Git blob IDs as that upstream commit, with 11 new planning docs local-only. See [upstream sync](UPSTREAM_SYNC.md). The [upstream issue list](https://github.com/k4ditano/k4/issues) showed zero open issues when first checked; closed issues were chiefly plugin publication submissions, too little evidence to infer broad user demand. Repository source remains the authority for this snapshot.

## What exists

`shell.qml` is a Quickshell `Scope` and creates one `PanelWindow` per `Quickshell.screens` screen. It wires K4 API services through `api/K4/Puente.qml`, exposes compatibility IPC on target `k4`, and chooses one global active plugin by `active` and integer `priority` (`shell.qml:34-109, 130-278`). `services/PluginManager.qml` loads catalog entries dynamically, destroys disabled instances, records errors, injects cross-plugin references, reads user plugins through `tools/plugins.py`, and supports retry and reload. `api/K4/Plugin.qml` defines the existing contract: `active`, `priority`, compact/expanded size, `view`, focus flags, background click and hover exit. There is already an activity arbiter; replacing it wholesale would break plugins.

The checked-in catalog has **31 built-in plugins** (`plugins/catalog.json`) and the external registry has **11 entries** (`plugins/registro.json`), which are listings, not installed or verified live instances. Source-file evidence by capability:

`README.md`, [plugin guide](k4-reference/PLUGINS.md), [public API](k4-reference/API.md), and `api/LEEME.md` supplement the source but do not supersede it. The external plugin loader/registry is already a real extension system, including QML views, settings, launcher contributions, indicators, IPC, plugin-owned JSON and processes. Its manifest `permisos` and `superficies` are checked by `tools/plugins.py`; **they are disclosure/static validation, not runtime isolation**. An enabled QML plugin runs inside the shell process and can use its privileges. Reload swaps the instance and handles QML cache paths, but a failed reload leaves the plugin broken rather than rolling back (`services/PluginManager.qml:200-450`, [plugin guide](k4-reference/PLUGINS.md)).

## Multi-monitor and interaction model

The host creates one edge window per screen. `Island.pantallaActiva` selects which monitor expands the globally winning plugin, with focus/requested-screen tracking; other monitors retain idle pills. `Island.rects`/`rectEn()` publish per-screen geometry. Fullscreen auto-hide is decided per screen through `Workspaces.lleno(screen.name)` (`shell.qml:278-560`, `services/Island.qml`, `services/Workspaces.qml`). Dock transition freezes its source monitor and uses that monitor's geometry (`plugins/Dual/DualPlugin.qml:212-260`). This is a useful starting point, but hotplug, scale changes, preferred-monitor policy, simultaneous activities on different displays, and drag crossing monitors need live proof. The design must not promise independent per-monitor expanded activities in v1 without reworking global arbitration.

**Side-placement API mismatch:** `Settings.posicionBarra` accepts `izquierda`/`derecha`; `shell.qml:290-372, 565-575, 1250-1315` anchors/rotates the compact host and `core/SiluetaIsla.qml` handles side shapes. `services/Island.qml:64` forwards the setting and `api/K4/Isla.qml:43` forwards that value, so `K4.Isla.posicion` can **actually return four values**. Its source comment and inherited [plugin guide](k4-reference/PLUGINS.md) still document only `arriba`/`abajo`. `plugins/Dual/DualPlugin.qml:444-455` handles all four; `plugins/Toast/BandaToast.qml:20-45` only checks `abajo` and positions every other edge as if top. Thus the host has real side code, but plugin-specific rendering is not comprehensively verified. Treat sides as **experimental/compatibility-only in v1** until live tests and public API docs are reconciled; do not promise full side parity.

**Notification ownership:** `services/Notifs.qml:482-503` creates `NotificationServer` with `actionsSupported: true`, marks arrivals tracked, and drives `latest`, count and toast. Panel history and action buttons use `server.trackedNotifications`; there is no separate daemon adapter or saved cross-daemon history store found. The [freedesktop notification specification](https://specifications.freedesktop.org/notification/latest-single/) defines one session-scoped D-Bus service. Existing swaync/mako/dunst ownership is a real conflict, not a stream k4 can passively mirror. See [D20](DECISIONS.md#d20-detail--notification-ownership).

The existing host already morphs width/height and handles idle, hover, click, keyboard focus and transient dismissal. `shell.qml:34-109` selects maximum priority and closes losing transients; `api/K4/Plugin.qml` exposes hover, focus and dismissal flags. `services/Notifs.qml` emits a `notified()` signal; some views subscribe directly. This is partial **host activity arbitration**, with state distributed between plugin booleans, services and host. There is no explicit lifetime/queue/restoration contract; a notification or volume change can be lost under a higher-priority view. Extend this arbitration rather than create a second owner.

## Quality, privacy and performance findings

- Large coupling points: `shell.qml` (~73 KB), `services/Editor.qml` (~143 KB), `services/Digivice.qml` (~122 KB), `plugins/Dual/Muelle.qml` (~83 KB), `services/Captura.qml` (~56 KB), `services/PluginManager.qml` (~45 KB). Size alone is not proof of a defect; transition, capture and render logic cross several of these files and deserve characterization before edits.
- Hyprland calls appear in `services/Workspaces`, `Ventanas`, `Submapas`, `Captura`, `Notifs`, `Digivice`, `plugins/Dual`, `HyprTheme`, `Pantallas`, `Atalaya` and installer/config files. `plugins/Dual/DualPlugin.qml:620-680` uses `hyprctl eval 'hl.*'` to focus without pointer warp. Do not hide this behind a generic window API without testing current Hyprland Lua behavior.
- Distro assumptions are separate. `dependencias.tsv` lists Arch package names; `instalar` supports non-Arch diagnosis but only installs automatically via pacman (`instalar:98-155, 251-340`). V1 does not need cross-distro installers. `instalar:760-787` can stop all `quickshell` processes by name while restarting k4; this is a high-impact installer risk to correct during implementation planning, with a targeted-process strategy.
- Likely cost centers: `plugins/Dual/DualPlugin.qml` polls `hyprctl -j clients` every 1.5 s **only while dock mode is active**; `services/Media.qml` polls position at 500 ms **only while playing with watchers**; `services/Bt.qml` has a 1.5 s vigilance timer; `services/Notifs.qml` uses a 5 s window check in a specific path; `services/Tokens.qml` has 5/60 s and 20 s timers; `services/Weather.qml` refreshes every 15 min; `services/Captura.qml` starts several tools during capture/recording; `plugins/Atalaya` uses live window copies and shaders. Measure idle and active modes before setting budgets or optimizing.
- `services/Wifi.qml` uses reactive Quickshell networking and scans only while its list is viewed; `services/Audio.qml` uses PipeWire object tracking; those are positive examples of event-led services.
- Outbound network audit: `services/Weather.qml` uses `ipwho.is` on missing/invalid saved location, Open-Meteo forecast and geocoding endpoints; `services/Media.qml` derives YouTube thumbnail, Twitch preview and website favicon URLs from MPRIS metadata, and `widgets/Artwork.qml` loads them when rendered; player-supplied `trackArtUrl` may itself be remote. `tools/agentes.py` reads local agent credentials and can call Anthropic's usage API for Claude limits; `plugins/Ask` may invoke the installed Codex CLI. Digivice can fetch Wikimon/digi-api franchise imagery to user cache. `tools/plugins.py` can fetch the upstream registry and plugin Git repositories, while `instalar` can clone the source; package search/install and user-enabled plugins can access remote sources. `tools/transcribir.py` prints an optional model-download command; it is not an automatic download in that path. These are feature-driven network paths, **not evidence of telemetry**. The accurate v1 promise is **no telemetry in Notchbar core; network-capable features/plugins disclosed and user-controllable where practical**, not global offline operation. `tools/plugins.py` manifest checks are static disclosure, not a sandbox; enabled third-party QML executes in process and can bypass a declared permission. Clipboard remains local in current source, with heuristic rather than universal secret exclusion.
- `LICENSE` is MIT, Copyright (c) 2026 k4ditano. Retain it and its notice. Bundled game art/data and third-party integrations require a separate asset/license inventory before distribution under a new identity; no ownership conclusion is made here.

Recent upstream changes that matter to architecture: [v1.0.1](https://github.com/k4ditano/k4/releases) moved Settings out of the island and described multi-monitor focus fixes; [v1.1.0](https://github.com/k4ditano/k4/releases) introduced Atalaya's live-window shader path; [2026-08-30 edge/dock work](https://github.com/k4ditano/k4/commit/78e9d0ed82e61f56da5bc78f0a186dd56098de95) broadened the dock journey beyond top/bottom; [2026-09-06 AMD GPU work](https://github.com/k4ditano/k4/commit/3ca83b3975b8604db9b1b8f6ab6697ded272f1d5) added sysfs metrics without `nvidia-smi`; [2026-09-06 localization work](https://github.com/k4ditano/k4/commit/6fe3b242cc45c8026fc9b326e5e6725eb47179e4) wrapped remaining interface strings. Those public commits explain relevant source evolution but do not prove this snapshot's exact SHA.

## Validation status

Read-only checks on this snapshot passed on 2026-09-25: `python3 tools/plugins.py` (31 built-ins), `python3 tools/api.py` (146 files), `python3 tools/guia.py` (5 pre-existing docs), `python3 tools/layouts.py` (275 files), `python3 tools/prueba_editar.py` (141 tests), `python3 tools/prueba_plugins.py` (63 tests), `python3 tools/prueba_rutas.py`, and `python3 tools/prueba_texto.py` (11 sinks). `.github/workflows/validar.yml` also runs `git diff --check`, which cannot compare against a meaningful base commit in this snapshot. These checks do not execute a live shell. There is no checked-in automated QML visual, Hyprland multi-monitor or performance gate. `quickshell`, `qmllint`, and `hyprctl` binaries exist here; `hyprctl monitors -j` reported one 1920×1080 monitor at scale 1, and no k4/Quickshell process was running when checked. Starting the full shell would alter the current desktop and start background services, so no runtime resource or multi-monitor measurement is claimed. Before implementation, baseline screenshots and traces should cover 1/2 monitors, top/bottom, fullscreen, DPI scaling, external plug/unplug, dock transition, focus, keyboard navigation and idle/active resource use.
