### D20 detail — notification ownership

The [freedesktop notification specification](https://specifications.freedesktop.org/notification/latest-single/) defines one session-scoped `org.freedesktop.Notifications` service. `services/Notifs.qml` unconditionally creates Quickshell `NotificationServer`, sets `actionsSupported`, tracks notifications, and feeds toast, history, unread count and actions. `shell.qml` eagerly touches the singleton. If swaync, mako, dunst or another daemon owns the bus name, k4 cannot also receive the same standard notification stream through this server. The exact Quickshell startup/error UI on name conflict needs a live test; no source evidence supports transparent coexistence or history mirroring.

V1 should offer **Own** and **External/off** settings. Own claims the bus name for full toast/history/actions; setup must tell the user to disable their other daemon through their own session configuration, without killing it automatically. External/off must avoid registering `NotificationServer`, leave the other daemon untouched, keep the rest of the surface usable, and show notification views as unavailable rather than empty history. Keep the `Notifs` singleton interface available with safe empty/no-op behavior because existing host and plugin bindings reference it. Installation should detect an existing owner and explain the choice; never silently take over. On migration, preserve the existing Own behavior when no conflict exists, warn on conflict, and keep non-notification settings/plugins intact. Test first launch, daemon already running, app restart and owner switching. A future daemon-specific adapter could use an **explicit documented API** if one exists; do not promise generic interception of another daemon's private history or actions. [Quickshell's NotificationServer documentation](https://quickshell.org/docs/v0.2.1/types/Quickshell.Services.Notifications/NotificationServer/) confirms tracked notifications and action support belong to the server instance.

## Implementation approval boundary

The approved direction supports a top Notch first-run default, one expanded activity owner, and staged Shelf references with copy-on-drag-out, subject to the **early DnD spike**. These defaults are recommendations to carry into implementation planning, not reasons to delay this documentation pass. If the spike changes Shelf's feasible user promise, return that material change for product review. Notification ownership [D20] is the new product-visible policy: Own for the full experience, External/off for users keeping another daemon, with honest unavailable states. Confirm this policy as part of implementation approval. Asset clearance remains a separate release gate; final name and artwork are later choices.
