Revisit conditions are explicit so a technical spike can change a proposal without pretending it was settled fact.

## Genuine input needed before implementation

1. **Approve or amend the v1 lock**, especially whether the Shelf is the single new workflow and whether existing optional modules remain shipped/enabled according to their current defaults. Recommended: yes.
2. **Shelf storage semantics:** approve “references with copy on drag-out” as the default, including a visible missing-source state. Alternative: copy into managed cache at drop time, which uses disk and introduces retention/privacy obligations. Recommended: references/copy.
3. **Default mode and display policy:** recommended Notch at the top on the preferred (initially focused/primary) monitor, compact idle affordance on other enabled screens, only one expanded owner; Dock and Hybrid opt-in. If the intended product should default to Dock or Hybrid, that affects first-run UI and test priority.
4. **Brand/assets:** final name and visual system are deliberately deferred. Before distributing a new product, decide whether existing game and image assets have compatible redistribution rights; the MIT source license alone does not prove all embedded assets are independently licensed. This is a release gate, not a reason to delete them now.

These questions can be answered together when reviewing the complete package. No broad consultation is needed for implementation details already resolved by source evidence.
