# Ordered implementation plan — begins only after product approval

Shelf DnD proof comes immediately after baseline/safety; design-system work follows before feature expansion. Preserve inherited behavior by default, using the [support tiers](V1_SPEC.md#support-tiers-and-release-gates); any removal needs an individual evidence record under [D14](DECISIONS.md). The [asset audit](ASSET_LICENSE_AUDIT.md) is a release gate, not an excuse for silent deletion.

## Stop/go rules

- The **milestone 2 Shelf spike runs before design-system/geometry/activity work** and remains separate from product implementation. A failed gate records the exact limitation and returns Shelf scope for product review; no silent workaround or removal.
- Notification delivery/history/actions require this app to own `org.freedesktop.Notifications`. Fresh first run chooses External/off if another daemon owns the name, or Own if it is unowned; migration preserves safely detectable intent/effective behavior but falls back non-destructively on a real conflict. The setting remains changeable. External mode must not impersonate another daemon or promise a mirrored notification center. Never kill or silently replace the existing daemon.
- Fresh Notchbar installations default Atalaya off; migrated k4 users keep their effective state even when it came from the inherited catalog default rather than a saved override. Revisit the fresh default only after the [D24](DECISIONS.md#d24-detail--atalaya-default-and-migration) measurements.
- File-reference clipboard and brightness HUD are conditional on real MIME/device paths. Their absence does not block text/image clipboard polish or the other supported HUDs.
- Visual quality is checked throughout, starting at milestone 3; milestone 9 is broader adoption, not a last-minute skin. Rendered proof includes focus, monitor, fullscreen, reduced motion and resource behavior, not screenshots alone.
- A plugin compatibility failure blocks the proposed API migration, not the ability to retain the existing API. The narrow compositor seam is extracted only at repeated Hyprland couplings identified in [ARCHITECTURE.md](ARCHITECTURE.md), not as a separate framework rewrite.

## Highest risks to monitor

1. Cross-app Wayland file DnD into/out of a layer-shell window, particularly drag cancellation and copy/move semantics.
2. One global activity owner versus multi-monitor focus, fullscreen and persistent dock state.
3. Existing `Dual` travel surfaces/Hyprland commands and their input/GPU cost.
4. Plugin API/lifecycle compatibility while activity and visual contracts evolve; enabled external QML still runs in process.
5. Clipboard file-reference MIME and secret detection; current source supports text/image and heuristic exclusion, not a universal guarantee.
6. Theme/blur/shader cost, optional module watchers, network defaults and bundled asset rights.

Each milestone records changes, commands/tests, hardware/runtime context and unmet scenarios. Passing static validators alone does not prove the live product.
