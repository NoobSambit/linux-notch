# Dependency inventory and packaging boundary

Source: [`dependencias.tsv`](../dependencias.tsv), [`instalar`](../instalar), QML imports and helper calls. This is an inventory, **not** a request to change packages. Package availability can drift; recheck at implementation. Current `dependencias.tsv` treats many feature dependencies as `base` because it describes the whole k4 installation, not the smallest new surface.

| Group | Current dependencies | Role / portability issue |
| --- | --- | --- |
| Core shell | Quickshell, Qt 6 Declarative/Wayland, Hyprland, Python, git | Quickshell/Qt are stack lock; Hyprland target is v1 compositor. `PanelWindow` needs Hyprland's `zwlr_layer_shell_v1` support; this is a wlroots/compositor protocol extension, not core Wayland or proof of GNOME/KDE compatibility. `qt6-multimedia`/FFmpeg support editor playback. |
| Visual assets | Meslo Nerd Font, Adwaita fonts, QML shaders/images | Icons rely on Nerd glyphs; check fonts and asset redistribution rights before new branding. |
| Capture/record/editor | grim, slurp, satty, wf-recorder, ffmpeg/ffprobe, ImageMagick, zenity; optional gpu-screen-recorder, whisper-cpp | Multiple external processes and codec/GPU variation. `gpu-screen-recorder` is detected in source, with wf-recorder fallback. Portal capture may help later but is not currently used as the main path. |
| Desktop utilities and protocols | wl-clipboard (`wl-copy`, `wl-paste`), fd, pactl/libpulse, WirePlumber (`wpctl`), NetworkManager (`nmcli`), BlueZ, libnotify, xdg-utils, xdg-user-dirs, desktop-file-utils; core `wl_data_device` DnD; compositor-supported data-control for unfocused clipboard watching | MPRIS/notifications/NetworkManager/BlueZ/UPower are freedesktop/D-Bus style APIs; PipeWire is a separate Linux service. Quickshell and CLI paths coexist. `ext-data-control-v1` or another supported data-control protocol is **not** core Wayland. |
| Notification ownership | `org.freedesktop.Notifications` session D-Bus name, currently Quickshell `NotificationServer` | Exactly one standard owner. Full toast/history/actions require Notchbar Own mode; External/off coexists with swaync/mako/dunst but cannot mirror their private history/actions. Installer must detect conflict, not stop another daemon. |
| Wallpaper and network | swaybg, curl, Open-Meteo forecast/geocoding, ipwho.is geolocation, optional Anthropic usage endpoint; media artwork URLs (player-provided, YouTube, Twitch, site favicons); optional Digivice Wikimon/digi-api images; registry/plugin Git fetches, source clone and package operations | These are verified feature/setup network paths, not telemetry. No global offline claim: disclose/control them where practical. Enabled third-party QML plugins run in-process; manifest permission checks are advisory, not a sandbox. |
| Optional tools | kitty, uwsm, yay, nvidia-smi, Claude/Codex CLIs, k4term, whisper-cli | Feature-specific requirements. App should show unavailable states instead of making them core unless necessary. |
| New Shelf | Core Wayland `wl_data_device` DnD plus Quickshell layer-shell target and local storage; no mandatory new package proposed | **Early isolated feasibility gate** tests `text/uri-list`, files/folders/multiple items, drag-out, action negotiation/cancel, missing source, keyboard and monitor cases before product work depends on it. Basket is separate. |

`instalar` maps Arch package names to some apt/dnf/zypper names for diagnosis but automatically installs only through pacman. It writes Hyprland config and may restart Quickshell processes globally; this deserves targeted safety work before recommending it to users with other Quickshell configurations. The v1 scope is a documented Hyprland manual path and dependency check, not installers for every distribution. A future packaging layer can translate logical capabilities into distro packages independently of the `CompositorBackend`.

The host imports `Quickshell.Hyprland` only in specific services/plugins, while MPRIS, PipeWire, Networking and Bluetooth are general Linux paths. This is the natural separation between compositor portability and distro packaging. The [Quickshell PanelWindow documentation](https://quickshell.org/docs/types/Quickshell/PanelWindow) and [portal ScreenCast interface](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.ScreenCast.html) should be consulted when a new mode/capture path is implemented. No dependency replacement is justified by this research.

See the exact protocol categories in [PORTABILITY.md](PORTABILITY.md) and the distribution provenance gate in [ASSET_LICENSE_AUDIT.md](ASSET_LICENSE_AUDIT.md). Screenshot/ScreenCast **XDG desktop portals** are D-Bus services backed by a desktop implementation; they are neither core DnD nor layer-shell/screencopy protocols. The core **no telemetry** promise does not override optional network behavior above.
